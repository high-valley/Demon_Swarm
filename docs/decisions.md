# 判断記録（ADR）

## ADR-001 Godot 4.7 + GDScript
- **決定**: 仕様書どおり Godot 4 系（4.7.2-stable）と GDScript。
- **理由**: Windows と Web を同じプロジェクトから書き出せる。C# は Godot 4 の Web 書き出しに非対応なので使わない。
- **影響**: エンジン更新時は `project.godot` と CI の `GODOT_VERSION` を同時に変える。

## ADR-002 Web 版は「スレッドなし」で書き出す
- **決定**: Web プリセットは `variant/thread_support=false`。
- **理由**: スレッドありの Web 版は COOP/COEP ヘッダーが必要で、GitHub Pages では設定できない。
- **影響**: 音声処理などがメインスレッドで動く。現状の規模では問題なし。

## ADR-003 レンダラーは Compatibility
- **決定**: `gl_compatibility`（WebGL2 / OpenGL3）。
- **理由**: Web で使える唯一のレンダラー。2D 中心なので Windows 版でも見た目の差はほぼない。

## ADR-004 バランス値は JSON、読込時に検証
- **決定**: `data/*.json` に置き、`DataLoader` で必須項目・参照整合性・値の範囲を検証。エラーがあれば起動時に一覧表示。
- **理由**: エディタ外でも差分が読みやすく、テストで壊れたデータを検出できる。Resource(.tres) はエディタでの編集は楽だが、手書き・レビューがしにくい。
- **保留**: データ量が増え、エディタ上で調整したくなったら Resource へ移行を検討。

## ADR-005 ロジックとノードを分離
- **決定**: `Simulation` はノード・描画・入力に依存しない `RefCounted`。表示は状態を読むだけ、通知は events キュー。
- **理由**: ヘッドレスで単体テストでき、固定ステップで seed 再現性を保てる。1000体対応で描画方式を変えてもロジックに影響しない。

## ADR-006 入力は InputRouter で「意図」に変換
- **決定**: キーボード/マウス/タッチはすべて `InputRouter` のシグナル（summon_at, order_at, dash など）に変換。
- **理由**: スマホでの確認を Web 版の要件にしたため。ゲームパッド追加もここだけで済む。
- **影響**: タッチ由来のエミュレーションマウスは無視する（二重入力防止）。

## ADR-007 日本語フォントを同梱（サブセット）
- **決定**: Noto Sans CJK JP（OFL）を ASCII・かな・JIS第1水準・使用文字にサブセット（約850KB）。
- **理由**: Web 版ではOSのフォントに頼れず、同梱しないと日本語が表示されない。全グリフ同梱は約16MBで読み込みが重い。
- **影響**: 第2水準の漢字を使ったら `tools/subset_font.py` を再実行。

## ADR-008 Steam 連携は Platform に閉じ込める
- **決定**: `Platform.steam_available()` を入口にし、GodotSteam は Windows 版でのみ有効化する予定。
- **理由**: Web 版と同じコードで動かし続けるため。
- **保留**: 実績・クラウドセーブの導入時期（MVP 対象外）。

## ADR-009 ウェーブの短縮モード
- **決定**: タイトルで「3分でボス」を選べる。出現スケジュールは時間圧縮、難度の伸びは実時間×1.6。
- **理由**: 10分待たずにボス戦まで確認するため。難度まで3.3倍速にすると序盤で詰むため伸びは緩める。
