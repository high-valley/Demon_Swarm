# ゲーム仕様書 02 — LIFE DEBT（仮）

- 文書種別: Game Design Document / MVP開発要件
- 版: v1.0（2026-10-16）
- 対象: Steam向けWindows PC、2D見下ろし型のシングルプレイ
- 目的: Claude Codeにアーキテクチャ設計と実装計画を作ってもらうための入力
- ステータス: 仮仕様。数値はプレイテストで調整する。

## 1. 一文で伝えるゲーム
**寿命がHP・通貨・スキル燃料・借金の担保になる**ローグライト。敵から時間を奪い、戦いに寿命を使い、未来の自分から借りた時間の返済に追われながら、寿命が階級を決める都市の最深部を目指す。

## 2. 差別化方針とIP注意
- 単に残り時間が減るアクションではなく「寿命経済と負債の選択」が攻略に直結することを中心にする。
- 2011年の映画『In Time / TIME/タイム』のテーマから着想を得るにとどめ、人物名・台詞・固有設定・デザイン・ストーリー展開を複製しない。独自の街、勢力、世界観を用意する。
- 既存ゲームにも「時間がHP/通貨」の例があるため、独占的・史上初のゲームメカニクスと主張しない。

## 3. デザインの柱（優先順）
1. 何をするにも寿命が減るため、毎秒・毎購入に緊張感が生まれる。
2. 敵を倒して寿命を奪うことで攻め続ける理由がある。
3. 時間の借金は強いが、返済という未来の敵を作る。
4. 攻撃ビルドと経済ビルドの両方が成立する。
5. 数字だけでなく時計・環境・敵の追跡で借金の代償を視覚化する。

## 4. コアループ
部屋に入る → 時計がリアルタイムで減る → 敵を倒して寿命回収 → 分岐（ショップ・強敵・回復/返済）を選ぶ → スキル・契約を強化 → 返済イベントを乗り越える → 最終ボスに到達。

## 5. 主要ルール（MVP）
- 時間寿命 `time_balance_sec` が唯一の生存リソース（初期900秒=15分）。ゼロで死亡。
- 戦闘中は実時間1秒ごとに寿命1秒減少。ポーズ・UI選択中・ロード中は減少しない。
- 被弾すると追加で寿命を失う（基本8秒/回）。無敵時間を設ける。
- 敵を倒すと時間片を落とし、拾うと寿命が増える（雑魚+20秒、エリート+90秒など仮値）。
- 基本攻撃は無料、強力なアクティブスキルは寿命を消費。
- 消費可能時間よりコストが大きい行動は不許可（借金契約による加算は例外として明示的操作）。
- 最大残寿命はMVPで3600秒。超えた分は切り捨て（画面に明記）。
- 1周: MVP 15〜20分を目標、3エリア×3〜4部屋＋ボス1体。マップの接続は分岐型で選択できる。

## 6. 操作
| 入力 | 行動 |
|---|---|
| WASD | 8方向移動 |
| 左クリック | カーソル方向へ基本攻撃 |
| 右クリック | 時間消費スキル（選択中） |
| Space | ダッシュ（クールダウンのみ、MVPでは寿命消費なし） |
| 1 / 2 / 3 | 装備したアクティブスキル選択 |
| E | ショップ/契約/出口のインタラクト |
| Esc | ポーズ（寿命減少停止） |
| Tab | 契約書: 現在寿命・借金・返済予定・効果を表示 |

## 7. 借金システム — 作品の主役
- 契約ポイント（ショップ/特定イベント）で「未来の寿命を借りる」。
- MVPの契約例: **300秒を即座に受け取り、3部屋後の入口で360秒を返済**（元本300+利息60）。
- 複数契約可能だがMVPでは最大2件に制限。返済予定は画面で明瞭に確認。
- 返済タイミングは「部屋遷移時」のイベントとして処理。実時間だけでなく部屋進行で強制されるため、タイマー停止の抜け穴がない。
- 返済可能: 自動で残寿命から引き落とし。
- 返済不能: 残寿命が0にならないよう差し押さえるのではなく、**取り立てイベント**へ。敵対する回収人が次の部屋に登場し、返済完了まで攻撃的に追跡する。通常の敵ドロップから一定率が差し押さえられ、回収人撃破で借金を清算（MVP）。
- 回収人が複数契約で重複出現しすぎないよう合算管理。
- 返済の成否・回収人発生・ドロップ差押えは契約データにより決定し、ゲーム中に追跡可能。
- 無限増殖防止: 契約受取上限、2件制限、部屋数に基づく満期、クリア判定までの返済処理を用意。

## 8. 戦闘とスキル（MVP）
| ID | 名称 | 寿命コスト | 内容 |
|---|---|---:|---|
| basic | 通常弾 | 0秒 | 単体連射。基礎DPSを担う |
| time_burst | 時間爆発 | 12秒 | 円形範囲ダメージ |
| temporal_dash | 時間切断 | 20秒 | 前方貫通斬撃＋短い敵スロー |
| drain_mark | 寿命刻印 | 8秒 | 指定敵の撃破時時間ドロップ+50% |

※時間爆発などの数値はゲームバランス用の仮値。時間消費が敵を倒すことで回収できるよう設計する。

## 9. 敵の種類（MVP）
| ID | 名称 | 行動 | ドロップ例 |
|---|---|---|---|
| debtor | 債務者 | 接近、低威力 | +20秒 |
| officer | 時間監視官 | 遠距離弾 | +25秒 |
| collector | 回収人 | 借金未返済時の追跡、追加寿命奪取 | 契約清算 |
| regulator_boss | 時間管理局長 | 範囲攻撃、召喚、時間盗取 | ボス討伐で勝利 |

敵のHPは別数値とする（寿命残高と敵HPを混同しない）。主人公だけ寿命=生存資源。

## 10. 経済・ショップ
- 価格はすべて寿命（秒）表示。通貨専用の別リソースを設けない。
- MVP例: 攻撃力+15%が120秒、時間回収効率+20%が180秒、最大寿命+300秒が150秒。
- ショップは非戦闘部屋。商品検討中・操作中は時間が減らない。購入後に部屋を出ると時間減少再開。
- 貧富の格差を表す「階級ゲート」はMVPに1種だけ実装。残寿命300秒以上なら高級ルート、未満なら危険な裏道。
- ゲートは通行の瞬間だけ判定、通過後に残高が減っても逆戻りしない。
- 価格変動、金利市場、街の人口変化、複数企業や派閥の経済シミュレーションはMVP対象外。

## 11. ローグライト進行
- 1周の構成: ランダムな部屋候補から分岐ルートを選択（通常戦・エリート・ショップ・契約・休憩）。
- 部屋マップはMVPではプリセット10種程度を接続。完全プロシージャル地形は後回し。
- 戦闘報酬でパッシブ強化を選択（例: 通常攻撃+15%、ドロップ回収範囲+20%、スキル寿命コスト−10%、回収人へ追加ダメージ）。
- 1回の周回内の強化は失われる。MVPで恒久強化はなし（プロフィール統計・アンロックは将来）。
- 毎周回seedを表示。敵構成、部屋候補、報酬候補は同じseedで再現可能にする。

## 12. HUD / 画面
1. タイトル: Play / Settings / Quit。
2. 戦闘HUD: 大型の寿命カウントダウン（mm:ss）、ボスHP、スキルアイコンとコスト、借金額と満期までの部屋数、分岐の方向。
3. マップ分岐画面: 次の部屋2〜3択。報酬タイプとリスクの表示。
4. 契約画面: 受取300、返済360、満期まで3部屋、未返済時のリスクを明示し同意して契約。
5. ショップ画面: 商品価格=寿命、購入後の残高プレビュー。
6. リザルト: 生存時間、累積獲得寿命、支払い総額、最大借金額、契約回数、到達エリア、勝敗、seed。
7. デバッグHUD: FPS、ルームID、ゲーム時間、経過時間、契約キュー、seed。

## 13. 世界観・演出（独自設計）
- 舞台: 時間を国家が配給する「時債都市」。住民は残寿命に応じて生活区域と身分が分かれる。
- 組織: 時間管理局、徴収組合、非合法な寿命銀行など。名称、外観、制服はオリジナルとする。
- 主人公: 身分証を剥奪された「回収不能者」。都市中枢の寿命管理システムに挑む。
- 戦闘中に時計の針・色・心音・画面端演出で寿命不足を伝える。点滅・明滅演出は設定で抑制可能。
- 物語は必要最小限、テキスト短め。MVPではカットシーンなし。

## 15. 技術的非機能要件
- 推奨: Godot 4系＋GDScript。Windows先行。将来のSteamリリースを想定。
- 生存タイマーの減算はdeltaに基づくゲーム内クロックで一元管理。画面ごとの独立タイマーは禁止。
- Pauseを含めた時計の停止/再開、イベントによる寿命増減、契約期日の処理順序を単体テスト可能にする。
- ドロップ・購入・契約での寿命増減は単一の残高管理APIを通し、二重決済・負数や上限逸脱を防ぐ。
- 数値はゲームデータから読み込み、調整可能にする。
- 乱数seed、決定的イベント処理、ゲーム統計ログ、セーブデータのschema_version。
- 解像度1920x1080基準、16:9。60FPS目標、最適化は計測に基づく。
- オフライン、個人情報収集なし。オンライン・課金・実績・クラウドセーブはMVP外。
- 仮アセットで開始、第三者の映画・ゲーム素材を無断使用しない。

## 16. 特に重要なエッジケース
1. 時間残高が0になった瞬間の死亡が1回だけ発生すること。
2. 購入と被弾が同フレームに発生しても残高不整合がないこと。
3. 契約満期をまたぐ部屋遷移で返済/追跡イベントが1回のみ発火すること。
4. 時間回収と寿命上限が正しく処理されること。
5. ポーズ・レベルアップ・ショップ・契約選択中は時間と敵AIが停止すること。
6. 返済できないときも、プレイヤーが回収人を倒せる逃げ道が残ること。
7. シード固定時の敵・報酬生成は再現可能。マウス動作やFPS差まで完全一致させる必要はない。
8. 死亡時、回収人討伐と契約返済などが重なる場合のイベント優先順位を設計で定義すること。

## 17. MVP受け入れ条件
1. プレイヤー移動、通常攻撃、寿命消費スキル、ダッシュができる。
2. 生存中は寿命が減り、被弾・スキル・購入で追加減少する。敵撃破で増える。
3. 時間0で敗北。ポーズ中は時間減少しない。
4. 分岐する部屋を選んで進行でき、ショップと契約イベントが機能する。
5. 借金の借入・満期・返済・不履行時の回収人イベントが動く。
6. 寿命残高によるルート条件分岐が1種類ある。
7. ボス撃破で勝利、リザルト・リトライが機能。
8. 固定seedとイベントログで主要なランダム分岐を再現できる。
9. 単体テストで寿命管理・契約処理の重要なエッジケースを検証できる。

## 18. MVP対象外・将来案
- 動的金利、証券取引、他住民の寿命マーケット、都市の地区ごとの社会シミュレーション、指名手配と派閥、将来の自分との戦闘、時間取引のPvP、オンライン要素。
- これらは核となる「残寿命と借金のせめぎ合い」が面白いか検証してから追加。

## 19. 初回プレイテストの問い
- 寿命の残高を支払う瞬間に悩みや快感があるか。
- 借金が単純なボーナスではなく、後のリスクとして機能するか。
- ゼロになる恐怖が理不尽な焦りになっていないか。
- 返済不能後に復帰できる可能性が十分あるか。
- 経済の選択とアクションの比率はどの程度が楽しいか。
